How the new formula works

Step 1 — weight fee  =  baseFee + (orderWeightKg × ratePerKg)
Step 2 — final fee  =  weight fee × multiplier

Real example — 3kg order, zone ISLAND_A:

Notice: Express uses the same config numbers — the multiplier does all the work. You configure once per zone, not twice.

1
Admin creates option types — one time setup. Regular (×1.0) and Express (×1.5).
POST /delivery/weight/option-type/save Authorization: Bearer <JWT> { "typeCode": "EXPRESS", "typeName": "Express", "multiplier": 1.5, "description": "30-minute delivery" }
2
Admin configures pricing per zone — sets base fee and rate per kg.
POST /delivery/weight/config/save Authorization: Bearer <JWT> { "zoneCode": "ISLAND_A", "optionTypeId": 2, "baseFee": 500, "ratePerKg": 200, "estimatedTime": 30, "estimatedTimeType": "MINUTES" }
3
Checkout calls /options when customer picks a zone — returns Regular + Express with live prices based on cart weight.
GET /delivery/weight/options ?zoneCode=ISLAND_A &totalWeightKg=3.0 x-source-code: MMC x-client-id: ... x-client-secret: ... Response → options: [ { optionTypeName: "Regular", finalFee: 1100.00, breakdown: "₦500 + (3kg × ₦200) × 1.0 = ₦1,100" }, { optionTypeName: "Express", finalFee: 1650.00, breakdown: "(₦500 + 3kg × ₦200) × 1.5 = ₦1,650" } ]
4
Customer picks Regular or Express → checkout calls /calculate to confirm the final fee to charge.
POST /delivery/weight/calculate x-source-code: MMC x-client-id: ... x-client-secret: ... { "zoneCode": "ISLAND_A", "optionTypeId": 1, "totalWeightKg": 3.0 } Response → { "finalFee": 1100.00, "breakdown": "..." }

Use finalFee as the delivery charge on the order. The breakdown string can be shown to the customer so they see exactly how it was calculated.
